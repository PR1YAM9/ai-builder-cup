# ClaimGuard AI 🛡️

**Multimodal insurance claim fraud & risk triage, powered by Gemini on Vertex AI and deployed on Cloud Run.**

Insurance fraud costs the industry billions every year, and adjusters spend hours manually cross-checking
photos, invoices, police reports and claimant statements. ClaimGuard does that cross-check in seconds:

1. **Reads every document.** Gemini extracts vendor, dates, line items and totals from invoices, receipts and reports (images or PDFs).
2. **Inspects the photos.** It describes the damage, its severity, and signs of staging, reuse or a mismatched vehicle or item.
3. **Cross-checks everything.** Narrative vs photos, photos vs invoice line items, invoice arithmetic, invoice totals vs claimed amount, and document dates vs the incident date.
4. **Applies policy rules deterministically.** Coverage limits, new-policy claims, late reporting, claim frequency and round-number amounts.
5. **Returns an explainable verdict.** A 0-100 fraud-risk score, APPROVE / MANUAL REVIEW / INVESTIGATE, red flags with cited evidence, and next steps.
6. **Answers follow-up questions.** The adjuster can ask "why this score?" or "draft a message requesting documents", with answers grounded in the claim record.

The final score is `max(AI score, rule floor)`, so a hard policy breach can never be scored as low risk.

## Architecture

```
Browser (static/index.html)
   │  multipart upload: metadata + statement + photos/docs
   ▼
Cloud Run · FastAPI (app/main.py)
   ├── rules.py ── deterministic policy checks ──┐
   └── Gemini 2.5 Flash on Vertex AI ◄───────────┘
         multimodal input, JSON-schema structured output (schema.py)
```

| Google Cloud | Used for |
|---|---|
| Gemini on Vertex AI | Multimodal document and photo understanding, reasoning, structured output, follow-up chat |
| Cloud Run | Serverless hosting of the API and UI |
| Cloud Build / Artifact Registry | Source-to-container build on deploy |

## Demo samples

The UI ships with four one-click sample claims (synthetic documents generated by `scripts/make_samples.py`):

| Sample | What to expect |
|---|---|
| 1 · Rear-end collision | Invoice and police report agree → **LOW**, approve |
| 2 · Inflated repair invoice | Line items add up to $4,750 but the total says $9,000; front-end parts on the invoice when the narrative says rear damage; invoice dated before the incident → **HIGH** |
| 3 · Lost phone, brand-new policy | Incident 10 days after policy start, phone bought for cash 2 days before the loss, claim at the coverage limit, police complaint says "lost on the metro on 30 Sep" (before the purchase) while the statement says "stolen at a cafe on 4 Oct", 3 prior claims → **HIGH** |
| 4 · Kitchen water damage | Consistent evidence but reported about 110 days late → **MEDIUM**, manual review |

Add your own damage photos to any sample to show the vision analysis.

## Integration API (plug-in for claims systems)

`/` is the product page and `/app` is the adjuster UI. Claims systems integrate through a versioned REST API. The interactive reference is at `/docs`.

| Endpoint | Purpose |
|---|---|
| `POST /v1/claims/assess` | Multipart claim fields + files → structured assessment. Pass your own claim number as `external_ref`. |
| `GET /v1/claims/{id}` | Fetch a stored assessment |
| `POST /v1/claims/{id}/ask` | Ask a grounded follow-up question (`{"question": "..."}`) |
| `GET /v1/rules` | Active rule configuration |

Per-deployment configuration (environment variables, passed through `deploy.sh`):

- `CLAIMGUARD_API_KEYS`: comma-separated keys required in the `X-API-Key` header on `/v1`. If unset, `/v1` is open (demo mode).
- `RULES_CONFIG`: JSON overriding rule thresholds and weights, e.g. `{"late_report_days": 60, "new_policy_days": 45}`. See `DEFAULT_RULES` in `app/rules.py`.

```bash
CLAIMGUARD_API_KEYS=key1,key2 RULES_CONFIG='{"late_report_days": 60}' bash deploy.sh
```

## Run locally

```bash
pip install -r requirements.txt
# Option A: AI Studio key
export GEMINI_API_KEY=...
# Option B: Vertex AI with your gcloud credentials
gcloud auth application-default login
export GOOGLE_CLOUD_PROJECT=your-project
uvicorn app.main:app --reload --port 8080
```

## Deploy to Cloud Run

```bash
gcloud auth login
gcloud config set project YOUR_PROJECT_ID
bash deploy.sh
```

The script enables the required APIs, grants the Cloud Run service account `roles/aiplatform.user`, and deploys from source.

## Notes
